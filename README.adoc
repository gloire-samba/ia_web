== 📖 Présentation du Projet

🎥 **Voir la démonstration vidéo (2 min) :** link:https://youtu.be/nESt4XXKj5A[Cliquez ici pour voir l'architecture en action sur YouTube]

Cette clé permet au microservice IA d'utiliser Gemini 2.5 Flash pour analyser vos requêtes (textuelles ou vocales via microphone), lire vos documents, analyser des fichiers vidéos (audio et image), et exécuter des tâches DevOps (tests et déploiement).
L'architecture est pensée pour être modulaire et démonstrative. Elle sépare distinctement les interfaces utilisateurs (deux clones parfaits en Angular et React), les serveurs relais (avec deux implémentations possibles pour prouver l'interopérabilité), et le cerveau analytique IA hébergé dans le Cloud.

== Prérequis
Pour exécuter ce projet localement, votre environnement doit disposer de :
* Node.js (v24+) et Angular CLI (v21+)
* Java JDK 25 (Assurez-vous que votre variable `JAVA_HOME` pointe vers la version 25)
* Python 3.12 ou supérieur
* **Docker Desktop** (Fortement recommandé pour le déploiement automatisé)

== ⚙️ Configuration des variables d'environnement

Avant de lancer les serveurs, vous devez configurer vos clés de sécurité et d'API. Le projet requiert deux fichiers de configuration : un `.env` pour Django/IA et un `application-secret.properties` pour Spring Boot.

=== 1. Fichier `.env` (Pour Django)
Créez un fichier `.env` à la racine de votre dossier **Django** (à côté de `manage.py`) et remplissez-le en vous basant sur ce modèle :

[source,properties]
----
# --- AUTHENTIFICATION SOCIALE ---
GITHUB_CLIENT_ID=votre_client_id_github_ici
GITHUB_CLIENT_SECRET=votre_secret_github_ici

GOOGLE_CLIENT_ID=votre_client_id_google_ici
GOOGLE_CLIENT_SECRET=votre_secret_google_ici

# --- SÉCURITÉ ---
JWT_SECRET_KEY=mettez_une_cle_secrete_tres_longue_ici

# clé secrete généré par django
SECRET_KEY ="django-insecure-0$c%5dvu9ssccb5kd7op%^ttwxaei=y2w&ni0bspa$=d5rrp)c"
----

=== 2. Fichier `application-secret.properties` (Pour Spring Boot)
Créez un fichier `application-secret.properties` dans le dossier `src/main/resources/` de votre projet **Spring Boot** :

[source,properties]
----
# ==========================================
# CLÉS JWT (JSON Web Token)
# ==========================================
jwt.secret=mettez_une_cle_secrete_tres_longue_ici
jwt.expiration=86400000

# ==========================================
# OAUTH2 GOOGLE
# ==========================================
spring.security.oauth2.client.registration.google.client-id=votre_client_id_google_ici
spring.security.oauth2.client.registration.google.client-secret=votre_secret_google_ici
spring.security.oauth2.client.registration.google.scope=profile,email

# ==========================================
# OAUTH2 GITHUB
# ==========================================
spring.security.oauth2.client.registration.github.client-id=votre_client_id_github_ici
spring.security.oauth2.client.registration.github.client-secret=votre_secret_github_ici
spring.security.oauth2.client.registration.github.scope=user:email
----

== 🏗️ Architecture et Composants
Le projet est divisé en 5 modules indépendants orchestrés par Docker.
*Cliquez sur les liens pour accéder à la documentation détaillée de chaque module.*

* 🎨 link:FRONT/README.adoc[**FRONT (Angular)**] : L'interface graphique de chat originelle sur le port 4200 (intègre la communication par texte et par microphone).
* ⚛️ link:FRONTREACT/README.adoc[**FRONTREACT (React)**] : L'interface graphique de chat alternative, développée avec Vite sur le port 5173 (intègre également la communication par texte et par microphone).
* ☕ link:BackSpring/README.adoc[**BackSpring (Java / Spring Boot)**] : Le premier serveur relais (Port 8080).
* 🎸 link:BackDjango/README.adoc[**BackDjango (Python / Django)**] : Le second serveur relais (Port 8000).
* 🧠 link:IA/README.adoc[**IA (Python / FastAPI)**] : Le code du cerveau IA, destiné à être hébergé sur Hugging Face. Il intègre désormais la transcription audio du micro et de puissants outils DevOps (tests unitaires et déploiement Git).
* 🐳 **`docker-compose.yml`** : Le chef d'orchestre. Ce fichier permet de démarrer les deux interfaces et les deux relais simultanément dans des conteneurs isolés avec une seule commande.

== 🔑 Tutoriel : Obtenir vos Clés et Configurer les Services externes

=== Étape 1 : Obtenir la clé Google Gemini (Pour l'IA)
Cette clé permet au microservice IA d'utiliser Gemini 2.5 Flash pour analyser vos requêtes (textuelles ou vocales via microphone), lire vos documents, et analyser des fichiers vidéos (audio et image).
1. Allez sur https://aistudio.google.com/[Google AI Studio].
2. Connectez-vous avec un compte Google.
3. Cliquez sur **"Get API key"** à gauche, puis sur le bouton bleu **"Create API key"**.
4. Copiez cette clé (elle commence généralement par `AIza...`). Gardez-la sous la main pour l'étape 2.

=== Étape 2 : Déployer le microservice IA sur Hugging Face
L'IA de notre application ne tourne pas sur votre machine, mais dans le cloud.
1. Créez un compte sur https://huggingface.co/[Hugging Face].
2. En haut à droite, cliquez sur votre profil puis sur **"New Space"**.
3. Donnez un nom au Space (ex: `mon-agence-ia`), choisissez la licence (ex: MIT), sélectionnez le SDK **"Docker"** (Blank), puis rendez le Space **Public**.
4. Cliquez sur **"Create Space"**.
5. Allez dans l'onglet **"Settings"** de votre Space, puis dans **"Variables and secrets"**.
6. Dans la section **"Secrets"**, ajoutez les variables suivantes :
   * Name : `GOOGLE_API_KEY`
   * Value : _La clé obtenue à l'Étape 1_.
   * Name : `HF_TOKEN`
   * Value : _Votre jeton d'accès Hugging Face (disponible dans votre profil HF, nécessaire pour générer les images manga)_.
7. Allez dans l'onglet **"Files"** de votre Space, et uploadez le fichier `main.py`, le fichier `requirements.txt`, le `Dockerfile` **ainsi que tous les fichiers Python commençant par `outils_`** de votre dossier IA.
8. Le Space va démarrer ("Building" puis "Running"). **Copiez l'URL de votre Space** et mettez-la à jour dans les fichiers `IaClientService.java` (Spring) et `services.py` (Django) pour que vos backends pointent vers ce nouveau cerveau.

=== Étape 3 : Obtenir le mot de passe d'application Google (Pour envoyer les billets par E-mail)

Pour des raisons de sécurité, Google n'autorise plus la connexion avec votre mot de passe habituel.
Il faut créer un "mot de passe d'application".

1. Allez sur les https://myaccount.google.com/security[Paramètres de sécurité de votre compte Google].
2. Activez la **Validation en deux étapes** si ce n'est pas déjà fait.
3. Cherchez **"Mots de passe des applications"** dans la barre de recherche des paramètres.
4. Générez un mot de passe (donnez-lui le nom "Agence Voyage").
5. Google va afficher un code de 16 lettres.
**Copiez-le sans les espaces** et collez-le dans vos variables `EMAIL_HOST_PASSWORD` (Django) et `spring.mail.password` (Spring).

=== Étape 4 : Configurer la connexion avec GitHub et Google (OAuth 2.0)

==== 🌐 Google Cloud Console
1. Allez sur la link:https://console.cloud.google.com/[Google Cloud Console].
2. Créez un nouveau projet.
3. Accédez à **API et services > Identifiants**.
4. Cliquez sur **Créer des identifiants > ID de client OAuth**.
5. Configurez l'écran de consentement en mode **"Externe"**.
6. **Origines JavaScript autorisées :**
   * Pour angular : `http://localhost:4200`
   * Pour React : `http://localhost:5173`
7. **URI de redirection autorisés :**
   * Pour Spring : `http://localhost:8080/login/oauth2/code/google`
   * Pour Django : `http://localhost:8000/accounts/google/login/callback/`
8. Notez votre **Client ID** et **Client Secret**.

==== 🐙 GitHub Developer Settings
1. Allez dans vos **Settings** GitHub > **Developer Settings** > **OAuth Apps**.
2. Cliquez sur **New OAuth App**.
3. **Homepage URL :** `http://localhost:4200` ( ici l'url que vous allez mettre sur  n'aura aucune importance, *mais assurez vous d'avoir aumoins mis soit l'url de 'angular ou soit celui de react* )
4. **Authorization callback URL :**
   * Pour Spring : `http://localhost:8080/login/oauth2/code/github`
   * Pour Django : `http://localhost:8000/accounts/github/login/callback/`
5. Enregistrez et générez un **Client Secret**.

=== Étape 5 : Obtenir un Jeton d'Accès GitHub (Pour le Déploiement CI/CD par l'IA)

Pour que l'IA puisse utiliser ses capacités DevOps (`outils_developpement`) et pousser automatiquement du code et des tests sur votre dépôt pour déclencher votre pipeline CI/CD, vous ne pouvez pas lui donner un lien classique (ex: `https://github.com/gloire-samba/ia_web.git`). 
Depuis plusieurs années, GitHub et GitLab interdisent la connexion avec un mot de passe classique pour des raisons de sécurité. Il faut obligatoirement utiliser un **Jeton d'Accès Personnel (Personal Access Token ou PAT)**.

Voici comment l'obtenir et l'assembler dans l'URL en 1 minute :

==== Étape A : Générer le Token sur GitHub
1. Connectez-vous sur votre compte GitHub, cliquez sur votre photo de profil en haut à droite, puis sur **Settings** (Paramètres).
2. Dans le menu de gauche, descendez tout en bas et cliquez sur **Developer settings** (Paramètres développeur).
3. Cliquez sur **Personal access tokens**, puis sélectionnez **Tokens (classic)**.
4. Cliquez sur le bouton **Generate new token** -> **Generate new token (classic)**.
5. Dans le champ **Note**, donnez-lui un nom pour vous en rappeler (ex: `Agent IA DevOps`).
6. Dans la liste des cases à cocher en dessous, **cochez impérativement les case principale `repo et workflow`** (cela donne le droit au jeton d'écrire et de pousser du code dans vos dépôts).
7. Descendez tout en bas de la page et cliquez sur le bouton vert **Generate token**.
8. GitHub va afficher une longue suite de lettres et chiffres commençant par `ghp_...` (ou `github_pat_...`). **Copiez immédiatement cette clé**, car elle ne sera plus jamais affichée ensuite !

==== Étape B : Comment construire votre lien d'appel ?
Pour que Git et l'IA puissent s'authentifier automatiquement en ligne de commande sans ouvrir de fenêtre interactive, la syntaxe officielle consiste à insérer le jeton juste après le `https://` et juste avant le `@github.com` :

[source,text]
----
https://TON_TOKEN@github.com/ton-pseudo/ton-depot.git
----

**Exemple concret :**
* Si votre lien classique est : `https://github.com/gloire-samba/ia_web.git`
* Et que le jeton généré par GitHub est : `ghp_88XxYyZz112233445566778899AAbbcc`
* **Le lien exact que vous devez envoyer dans le chat à votre IA sera :**
+
[source,text]
----
https://ghp_88XxYyZz112233445566778899AAbbcc@github.com/gloire-samba/ia_web.git
----
_(Note : Pour GitLab, le principe est exactement le même : vous générez un "Access Token" dans les paramètres de votre profil GitLab commençant par `glpat-...`, et vous l'insérez sous la forme `https://glpat-xxxxxx@gitlab.com/...`)._

== 🚀 Guide de Lancement et d'Arrêt Global

Vous avez deux possibilités pour lancer ce projet : la méthode automatisée (via Docker) ou la méthode manuelle.

=== Méthode 1 : Lancement avec Docker (Recommandé 🌟)
C'est la méthode la plus simple et la plus robuste.
Elle garantit que l'application fonctionnera avec les bonnes versions des langages sans rien polluer sur votre machine.
**Avantage majeur : les deux interfaces et les deux serveurs relais tournent en parallèle !**

**Démarrer l'application :**
.
Ouvrez un terminal à la racine absolue du projet.
.
Lancez la commande suivante (ajoutez `sudo` sous Linux si nécessaire) :
+
[source,bash]
----
docker compose up --build
----
.
Les applications sont disponibles sur :
  * **http://localhost:4200** pour l'interface Angular.
  * **http://localhost:5173** pour l'interface React.
_Grâce à Docker, tout est allumé simultanément en arrière-plan. Vous pouvez basculer d'une interface à l'autre et interroger Spring Boot ou Django en temps réel !_

**Arrêter l'application :**
.
Allez dans le terminal où défilent les logs.
. Appuyez sur **`Ctrl + C`** pour éteindre tous les serveurs en douceur, puis tapez la commande `docker compose down -v` pour supprimer les volumes et les réseaux.
---

=== Méthode 2 : Lancement Manuel (Développement)
Si vous souhaitez modifier le code et voir les changements en temps réel sans recompiler les conteneurs Docker, vous devez lancer les modules individuellement.
⚠️ **Règle d'or de la méthode manuelle :** N'allumez qu'**UN SEUL** serveur relais à la fois pour éviter les conflits réseau et la surcharge mémoire.

**1. Lancer l'Interface (Choisissez Angular ou React)**

_Pour Angular :_
[source,bash]
----
cd FRONT/votre-dossier-angular
npm install   # La première fois uniquement
ng serve
----

_Pour React :_
[source,bash]
----
cd FRONTREACT/front-react
npm install   # La première fois uniquement
npm run dev
----

**2. Lancer un Serveur Relais (Choisissez votre Back-end)**
Ouvrez un *second* terminal et choisissez le moteur de votre choix.
Dans l'interface, assurez-vous de sélectionner le bouton correspondant au serveur que vous venez d'allumer !

**Option A : Lancer Spring Boot (Java)**
[source,bash]
----
cd BackSpring/backspring
./mvnw spring-boot:run
----

**Option B : Lancer Django (Python)**
[source,bash]
----
cd BackDjango/votre-dossier-django
source venv/bin/activate  # Ou venv\Scripts\activate sur Windows
pip install -r requirements.txt # La première fois uniquement
python manage.py runserver
----

**Arrêter et changer de relais manuellement :**
* Appuyez sur **`Ctrl + C`** dans le terminal du serveur en cours d'exécution.
* _Exemple : Pour passer de Spring à Django, coupez le terminal Spring, puis ouvrez le dossier Django et lancez la commande de démarrage Python._
